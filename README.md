## 1. Төслийн тухай

Энэхүү лабораторийн ажлаар Уншлагын жагсаалт веб аппликейшнд Session-Based Test Management (SBTM) аргаар туршилт хийж, хэрэглэгчийн интерфейс болон API түвшний согогуудыг илрүүлэв.

## 2. Орчин

- Үйлдлийн систем: Windows 11
- Хөтөч: Google Chrome
- Сервер: Node.js (`app.js`)
```

```
- Хаяг: http://localhost:3000
- API шалгалт: `curl.exe`
- Хувилбарын удирдлага: Git

## 3. Charter

- **Судлах:** Ном нэмэх, хайх, устгах болон API үйлдлүүд.
- **Ашиглах:** Хоосон оролт, буруу өгөгдөл, том/жижиг үсгээр хайх болон API хүсэлтүүд.
- **Илрүүлэх:** Оролтын баталгаажуулалт, хайлт, өгөгдлийн бүрэн бүтэн байдал, алдааны мессеж болон API хариултын согогууд.

### Сонгосон аялалууд

1. **Supermodel (GUI):** Хуудасны талбар, товч, мессеж болон хүснэгтийг шалгах.
2. **Couch Potato:** Хоосон болон дутуу оролтоор баталгаажуулалтыг шалгах.
3. **Saboteur:** Буруу өгөгдөлтэй API хүсэлт илгээж шалгах.
4. **Fed-Ex:** Ном нэмэх, хайх, устгах үед өгөгдөл зөв дамжиж байгаа эсэхийг шалгах.

## 4. Туршилтын үр дүн

Туршилтын явцад дараах боломжит согогуудыг ажиглаж, тайлан бэлтгэв.

- Буруу хайлт хийхэд амжилтын мэдэгдэл гарч байгааг шалгасан.
- Гарчиг, зохиогчийн талбарт буруу утга оруулахад үүссэн үр дүнг шалгасан.
- HTML тусгай тэмдэгтүүдийг харуулах байдлыг шалгасан.
- Байхгүй ID-тай ном устгах API хүсэлтийн хариуг шалгасан.
- `/old` хуучин хувилбарын хуудас Internal Server Error буцаасныг тэмдэглэсэн.

Согог тус бүрийн дэлгэрэнгүй мэдээллийг `bugs/` хавтаснаас үзнэ үү.

## Дүгнэлт

## Дүгнэлт (Debrief)

### Аль аялал хамгийн үр дүнтэй байсан бэ?

Туршилтын үеэр Supermodel, Couch Potato, Saboteur болон Fed-Ex гэсэн дөрвөн аяллын дагуу “Уншлагын жагсаалт” веб системийг шалгасан. Эдгээрээс **Saboteur аялал нь системийн алдаа, оролтын баталгаажуулалт болон хэвийн бус нөхцөлд гарч буй асуудлыг илрүүлэхэд хамгийн үр дүнтэй** байсан. Учир нь энэ аяллын хүрээнд хоосон талбар, буруу форматтай он, байхгүй номын ID болон буруу оролтын үед систем хэрхэн хариу үйлдэл үзүүлж байгааг шалгах боломжтой байсан. Мөн Supermodel аялал нь системийн үндсэн үйлдлүүдийг шалгахад, Couch Potato аялал нь хэрэглэгчийн ердийн хэрэглээ болон хайлтын үйлдлийг судлахад, Fed-Ex аялал нь өгөгдөл боловсруулах болон үйлдлүүдийн үр дүнг шалгахад тусалсан. Ном нэмэх, хайх, устгах болон статистикийн мэдээллийг хооронд нь харьцуулснаар системийн өөр өөр хэсэгт илэрч буй зөрүүг анзаарах боломжтой болсон.

### Charter-аас гадуур ямар асуудал илэрсэн бэ?

Туршилтын явцад анх төлөвлөсөн аяллуудаас гадна API-ийн хариу төлөв, HTML тэмдэгтийн дүрслэл болон байхгүй нөөцөд хандах үеийн системийн хариу үйлдлийг нэмж шалгасан. Тухайлбал, `/old` замд хандахад `Internal Server Error` буцаж байгаа эсэх, байхгүй номын ID-аар DELETE хүсэлт илгээхэд ямар хариу ирж байгааг судалсан. Мөн HTML-д тусгай тэмдэгт оруулахад тэдгээр нь зөв дүрслэгдэж байгаа эсэхийг шалгасан. Эдгээр нэмэлт туршилтууд нь зөвхөн хэрэглэгчийн интерфейсийн харагдах байдал бус, серверийн хариу үйлдэл болон өгөгдөл боловсруулах логикийг хамруулан судлах боломж олгосон. Зарим тохиолдолд серверээс амжилттай гэсэн төлөв буцаж байгаа нь тухайн үйлдэл бизнес логикийн хувьд зөв ажиллаж байгааг дангаараа батлахгүй гэдгийг анхаарах хэрэгтэй. Иймээс дараагийн session-д API-ийн статус код, буцаж ирж буй өгөгдөл болон хэрэглэгчийн интерфейс дээр харагдах үр дүнг хооронд нь тулган шалгах шаардлагатай. Charter-аас гадуур илэрсэн асуудлуудыг дараагийн туршилтын session-ийн charter-д тусгаж, илүү нарийвчлан шалгах нь зүйтэй.

### Аль алдааг автомат тестээр илрүүлэх боломжтой байсан бэ?

Энэ session-д Playwright болон бусад автомат UI тестийн хэрэгсэл ашиглаагүй. Туршилтыг браузер дээр гараар хийж, API-ийн зарим үйлдлийг `curl.exe` ашиглан шалгасан. Гэсэн хэдий ч илэрсэн зарим алдааг цаашид автомат тест болгон хэрэгжүүлэх боломжтой. Жишээлбэл, номын нэр болон зохиогчийн нэр хоосон үед ном нэмэгдэхгүй байх, хайлтын үр дүн болон статистикийн тоо хоорондоо нийцэж байх, буруу форматтай он оруулахад систем зохих алдааны мэдэгдэл харуулах зэрэг шалгалтуудыг автомат тестээр давтан гүйцэтгэж болно. Мөн байхгүй ID-аар ном устгах хүсэлт илгээхэд сервер зөв төлөв код болон ойлгомжтой хариу буцааж байгаа эсэхийг API тестээр шалгах боломжтой. Харин товчлуурын өнгө, текстийн байрлал, мэдээллийн харагдах байдал зэрэг визуал асуудлыг гараар шалгах эсвэл тусгай visual regression тест ашиглах шаардлагатай байж болно. Туршилтын үеэр гэнэтийн байдлаар илэрсэн асуудал, хэрэглэгчийн үйлдлийн дараалалтай холбоотой зөрүүг зөвхөн урьдчилан бичсэн автомат тестээр бүрэн илрүүлнэ гэж үзэх боломжгүй. Иймээс автомат тест болон exploratory testing нь бие биеэ орлох бус, харин харилцан нөхөх аргууд юм.

### Ерөнхий дүгнэлт

Энэхүү session-ийн үр дүнд системийн үндсэн үйлдлүүдийг шалгахаас гадна хэвийн бус оролт, API-ийн хариу үйлдэл болон өгөгдлийн нийцэлтэй холбоотой асуудлуудыг судалсан. Илэрсэн асуудлуудыг тус тусад нь баримтжуулж, шаардлагатай тохиолдолд нотлох зураг болон командын үр дүнгээр баталгаажуулсан. Туршилт нь зөвхөн системийг зөв ашиглах нөхцөлийг шалгах бус, харин буруу оролт болон урьдчилан тооцоолоогүй нөхцөлд хэрхэн ажиллаж байгааг судлахын ач холбогдлыг харуулсан. Дараагийн session-д өмнөх асуудлууд засагдсан эсэхийг дахин шалгах, API-ийн хариу болон интерфейсийн үр дүнг тулгах, мөн давтагддаг шалгалтуудад автомат тест нэвтрүүлэх боломжийг судлах шаардлагатай.
